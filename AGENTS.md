# Architecture rules

- Content hierarchy is Campaign Brief → Master Content Object → post_cards (platform variants, linked via brief_id / master_content_id); generate variants from an approved brief, not standalone, so every output traces to one approved message.
- Brief edits to strategic fields bump the version, revert approval, and flag linked master objects stale via a DB trigger.
- Brief AI generation runs in the generate-from-brief edge function using the caller's session.
- AI Preflight results live in `preflight_reviews` (latest row per post card, tied to a draft checksum); approval and export are gated client-side until the latest non-stale review passes, is acknowledged (advisory), or is overridden with a logged reason; rule checks are shared from `supabase/functions/_shared/preflightRules.ts` so app and edge function agree.
- Posts are identified to users by a sequential `post_number` shown as SM-NNNN on every screen (shared helpers in `src/components/tracking/PostTracking.tsx`); cross-screen jump links use `?post=<id>` so one ID tracks a post from draft to posted.
- Buyer/workspace configuration (company profile, org type and labels, plan limits, setup progress, auto-admin domain) lives in the single-row `workspace_settings` table, never in code, so this master build can be remixed into blank sold copies and receive updates without overwriting buyer setup; SocialMotive branding itself is fixed in code.
- Workspace roles (owner/admin/editor/reviewer/viewer) live in `user_roles`; owners also hold `admin` and non-admins also hold `member` so existing RLS keeps working, while restrictive policies via `can_create_content`/`can_edit_content` enforce editor/reviewer/viewer limits server-side.
- Team changes go through security-definer RPCs (`set_workspace_role`, `transfer_ownership`, `remove_workspace_user`) and invites are applied in `handle_new_user`, so role escalation can't happen client-side.
- Notification email always sends through the workspace-configured provider (SendGrid or SMTP) via the `notifications` edge function; credentials live in a service-role-only table, never in code or the browser, so each sold copy connects its own email account.
- Guardrail baselines live in `supabase/functions/_shared/guardrails.ts`; per-client toggles/custom terms in `guardrail_settings`; strategy generators (AI, document, presets) all produce one reviewable draft shape applied client-side, so nothing is saved without human selection.
- Repurpose ideas are generated by the `repurpose-content` edge function (caller session, approved posts or generation-allowed assets only) into `repurpose_suggestions` with a full draft; a human edits and sends each to the queue as a new Draft post linked via `repurposed_from_id`, so reuse stays traceable and still passes Preflight/approval.
- Executive voice profiles live in `voice_profiles` and are analyzed by the `analyze-voice` edge function (reviewable draft, human saves); `generate-from-brief` accepts `voice_profile_id` and injects the person's traits into every variant, stored on `post_cards.voice_profile_id`.
- Content Motive Score™ is computed in `supabase/functions/_shared/motiveScore.ts` inside `preflight-review` (deterministic hook/strategic/platform/originality sub-scores plus the AI voice score) and stored as `motive_score`/`motive_breakdown` on `preflight_reviews`; UI rendering is shared via `src/components/preflight/MotiveScore.tsx`.
- Billing lives in `subscription_tier_definitions` (current rows edited in place; no grandfathering) + `credit_weight_definitions` and the service-written `workspace_billing` row; shared commercial constants live in `src/lib/pricing.ts` so UI, tests and the payment catalog agree.
- Metered actions go through `consume_usage` (dry-run pre-check, then deduct) in UI (`useCreditGate`) and every AI edge function; it is the only hard stop (100%), while `evaluate_anomalies` only records notification alerts, so legitimate work is never paused early.
- Video uses separate `video_draft`/`video_premium` clip buckets (included allowance + one-month rollover + 12-month packs in `addon_grants`), never media credits, so video cannot drain image allowance.
- Launch add-ons are admin-granted through idempotent `grant_addon` (unique request key); self-serve top-up checkout stays off per instance until that instance's payments are confirmed.
- Scheduled delivery runs in-database via pg_cron `process_scheduled_posts` (25-post cap, SKIP LOCKED, runs logged in `publish_runs`) and only stages attempts; live dispatch is reserved for the inactive `dispatch-scheduled-posts` function so no platform call happens without approved apps.
- Subdirectories (e.g. `src/`, `supabase/functions/`) have their own `AGENTS.md`; read it before changing files there.
